Valmo Partner App

FE Loss Report Card Redesign

Context & Objective

The Problem

When a loss is attributed to a Pilot (FE), money is deducted with no explanation or chance to respond[cite: 2]. The goal of the Valmo KRD is to build a Losses section giving pilots visibility, proof, and a choice to accept or dispute before deduction[cite: 2].

Why this Presentation?

An audit was conducted on the current live React prototype implementation of the L1 (loss detail) and L2 (sub-flow) screens[cite: 1]. The audit revealed significant inconsistencies in visual design and structural flaws that prevent scalability[cite: 1].

This presentation outlines the findings of the audit and proposes a new, unified template architecture to ensure the UI can handle business growth without requiring continuous code rewrites[cite: 1].

The Deliverable Mandate: The audit and template spec must be approved first; only then will the code refactoring occur[cite: 1]. This presentation serves as the published shareable artifact to facilitate that approval[cite: 1].

Canonical Taxonomy & Lifecycle

The architecture must strictly follow the KRD definitions, not the hardcoded prototype[cite: 1].

1. Reason Codes (The Real List)

The load-bearing scalability requirement (NFR-5) demands that reasons are config-driven and the UI can grow to ~10 reasons without redesigning[cite: 1, 2].

  • ICUD image junk: "Delivery photo not clear" (Debitable, 2 images)[cite: 1, 2].
  • Pickup image junk: "Pickup photo not clear" (Debitable, 2 images)[cite: 1, 2].
  • Pickup-vs-QC mismatch: "Secondary QC mismatch" (Debitable, 4 images)[cite: 1, 2].
  • Wrong-RVP pickup: Info only, never debited[cite: 1, 2].
  • Lost in Field (LiF): Already deducted day-0, recoverable via return[cite: 1, 2].

2. Case-State Lifecycle

The UI must gracefully handle these central DB data states[cite: 1]:

  • ATTRIBUTED: Open case, 7-day window[cite: 1].
  • OPEN_DISPUTE_PAUSED: Dispute paused due to consecutive wrong disputes[cite: 1].
  • IN_DISPUTE: 100% human review, 7-day SLA[cite: 1].
  • ACCEPTED: Business selects Y% for full deduction[cite: 1].
  • INFO_ONLY: Terminal state, no money at risk[cite: 1].
  • DEBITED: Posts on resolution date[cite: 1].
  • WAIVED: Auto-waive triggers on SLA breach[cite: 1].
  • NOT_DEDUCTED: Accepted but business chose not to select[cite: 1].
  • RETURNED_CREDITED: LiF parcel returned successfully[cite: 1].

Current-State Audit & Gap Register

The current prototype uses a ~90-line `if/else` chain to produce nine disconnected variants, breaking core KRD logic[cite: 1]. Click to expand critical gaps.

Prototype: Says "Find it by 20 Aug or ₹40 will be deducted" (future)[cite: 1].
KRD Rule: LiF is already auto-deducted on day-0[cite: 1, 2]. The app must frame this as a recovery: "₹X already cut — return by date to get it back"[cite: 1].

Prototype: No detail screen shows the payout pointer[cite: 1].
KRD Rule: F22 requires every debited item to name its exact payout date, section, and line[cite: 1, 2]. Currently, claims losses have no ledger surface at all in Payment Details[cite: 1].

Prototype: `lost` and `wdetail` are reason-shaped, while `pending` and `review` are state-shaped[cite: 1].
Impact: Adding a 6th reason means creating a whole new screen and branch. This directly violates NFR-5 ("grows to ~10 without redesign")[cite: 1, 2].

Prototype: The audio chip exists but only triggers `stopPropagation()`, lacking TTS[cite: 1].
KRD Rule: F10 marks this as P0 (TTS in app language on every explanation block)[cite: 1, 2].

Amounts like ₹120 and dates like "19 Aug" are hardcoded inside branches instead of derived from the record[cite: 1]. Evidence sets are per-item instead of mapped by reason code as required by F8[cite: 1]. No full-image evidence viewer exists[cite: 1].

Proposed Architecture: Two Orthogonal Axes

Everything the prototype currently branches on collapses into two inputs: L1 detail = f(reasonCode, caseState)[cite: 1].

Axis 1: Reason Registry (Config)

Owned by business[cite: 1]. Decides what happened[cite: 1].

  • Evidence set mapping[cite: 1].
  • Explanation copy & tip[cite: 1].
  • Money semantics (debitable vs info_only)[cite: 1].
  • Available remedies & payment line[cite: 1].

Axis 2: Case-State Table

Decides where it is[cite: 1].

  • Banner tone + statement[cite: 1].
  • Which action block appears[cite: 1].
  • Whether a tracker shows[cite: 1].
  • What the footer promises[cite: 1].

The Payoff

No screen is ever added for a new reason[cite: 1]. A new reason is just a row in the reason registry, and it automatically inherits a shape Pilots already know[cite: 1].

L1 Slot Template (The IA Invariant)

A fixed slot order ensures consistency. Click on any slot to see how the Reason and State axes populate it[cite: 1].

1. Identity Reason Code
Filled by reason. Renders the FE-facing reason name and AWB. Never skipped[cite: 1].
2. Status Banner Case State
Filled by state. Controls tone, money statement, and voice-out toggle. Never skipped[cite: 1].
3. Money & Remedy Reason + State
Promoted directly under the status banner (10 Sep): once the Pilot has read what happened to their money, where that money now sits is the next thing they need — before the proof or the explanation. Shows payment pointer (debited), recovery card (LiF), or credit pair (returned). Skipped if info_only[cite: 1].
4. Evidence Reason Code
Filled by reason configuration. Displays grouped photo sets. Skipped if reason specifies 'none' (e.g., LiF)[cite: 1].
5. Explanation Reason Code
Filled by reason. Prints "What happened" copy (or a tip if evidence is missing). Never skipped[cite: 1].
6. Progress Tracker Case State
Filled by state. Shows 3-step timeline. Skipped for non-awaiting states[cite: 1].
7. Action Block Reason ∩ State
Offers choices (Accept/Dispute, add-side, recovery CTA) or paused notice. Skipped on terminal states[cite: 1].
8. Consequence Footer Case State
Filled by state. Displays silence consequence or closure statement. Never skipped[cite: 1].

Strict Visual Rules & Coverage

Visual tone is chosen purely by money position, never by severity or reason[cite: 1]. This ensures new reasons don't invent new visual languages[cite: 1].

Risk (Yellow/Orange)

Money at stake, action open[cite: 1].
States: ATTRIBUTED, COOL-OFF, LiF recovery[cite: 1].

Progress (Blue)

In flight, nothing cut yet[cite: 1].
States: IN_DISPUTE, ACCEPTED, INFO_ONLY[cite: 1].

Resolved Good (Green)

No money lost[cite: 1].
States: WAIVED, NOT_DEDUCTED, RETURNED_CREDITED[cite: 1].

Resolved Neutral (Grey)

Money cut, case closed[cite: 1].
States: DEBITED[cite: 1].
